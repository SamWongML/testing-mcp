**Handoff notes (P11 — 2026-07-25):**

- **Shape.** P11 is the deployment layer. Two new adapters behind the P6 seams
  (`DynamoTaskStore` → `TaskStateStore`, `S3ArtifactStore` → `ArtifactStore`), one selection
  module that makes the backing a config choice, a CDK app, and one container image that runs
  three roles. No representation change; the engine stays pure (no AWS import anywhere under
  `packages/engine`). New deps: `@aws-sdk/{client-dynamodb,lib-dynamodb,client-s3,s3-request-presigner}`
  on `@atp/store`, `@aws-sdk/client-ecs` + the two OTLP exporters on `@atp/mcp-server`,
  `aws-cdk-lib`/`constructs`/`aws-cdk` on the new `infra` workspace package.

- **Everything stays off by default.** `TASK_STORE=postgres` and `ARTIFACT_STORE=local` are the
  defaults, so dev/test/CI run exactly as they did in P10. `RUN_TASK_ENABLED`, `AUTH_ENABLED`,
  and `OTEL_ENABLED` likewise default off.

- **Files.**
  - `packages/store/src/aws/` — `attributes.ts` (the §16.2 item shape; `state`/`error`/`ttl` are
    DynamoDB **reserved words**, so every expression aliases its names), `client.ts`,
    `dynamo-tasks.ts`, `dynamo-idempotency.ts`, `s3-artifacts.ts`, `select.ts`, `test-aws.ts`
    (exported as `@atp/store/testing`).
  - `packages/store/src/db/url.ts` — `resolveDatabaseUrl`: prefers `DATABASE_URL`, else derives
    one from the RDS-managed Secrets Manager JSON.
  - `packages/mcp-server/src/` — `exporters.ts` (console↔OTLP selection), `run-task.ts` (the
    §11.3 mode-2 launcher), `main-migrate.ts` (`MODE=migrate`), plus `taskStoreFor` in
    `tasks.ts` and trace propagation in `telemetry.ts`.
  - `infra/` — `bin/app.ts`, `src/{network,data,ecs,observability}-stack.ts`, `src/metrics.ts`,
    `cdk.json`. `Dockerfile` + `docker-entrypoint.sh` at the repo root.

- **`DynamoTaskStore` design notes.** Writes go through `UpdateItem`, not `PutItem`, even for
  the full-replace `put` — that is what lets `created_at` survive a replace via
  `if_not_exists` (SEP-1686 `Task.createdAt` must be *first* creation, which the Postgres store
  gets free from an insert-only column default). `create()` is a conditional `PutItem`
  (`attribute_not_exists`), the direct analogue of `ON CONFLICT DO NOTHING`. Reads are
  `ConsistentRead: true`: a stale replica read could resurrect a cancelled run. `deleteExpired`
  is a real scan-and-delete sweep, because native DynamoDB TTL reaps only "within a few days"
  and never at all on dynamodb-local — both run, and deleting an already-deleted key is a no-op.

- **The store-selection seam (exit criterion 3).** `createTaskStoreProvider(config)` returns
  `{ forDb, transactional, idempotency, close }`. `forDb(db)` takes the caller's Db/transaction
  because the Postgres store must **join** the caller's transaction (that is what makes
  create-task + enqueue atomic); DynamoDB ignores it. `submitRun` branches on `transactional`:
  the Postgres path is unchanged, and the DynamoDB path claims an idempotency key first (so the
  run id is minted *independently* of the key — the stage-1 path had to make the key **be** the
  run id), creates the task item, then enqueues, failing the task if the enqueue throws. A
  claim pointing at a run with no task is **adopted** rather than trusted, which heals the
  crash window between claim and create. Everything else in the package reads task state
  through `taskStoreFor(ctx, db)`.

- **Two cross-stack dependency cycles, both real.** (a) `data.database.connections.allowFrom(service)`
  puts an ingress rule referencing an `ecs` construct into the `data` stack, while `ecs` already
  reads `data`'s table ARNs. (b) The pattern-created ALB security group did the same to
  `network`. Both are fixed by having `NetworkStack` own the app **and** ALB security groups and
  constructing the ALB *instance* here, handing it to the pattern via `loadBalancer` (the
  pattern is still used — it just no longer creates the offending SG). Rule of thumb recorded in `.claude/rules/infra.md`: grant
  ingress **downward**, never upward.

- **`cdk synth` is deliberately Docker-free.** The ecs stack references a pushed `imageUri`
  rather than `ContainerImage.fromAsset`, so CI can synth on every PR without a daemon. CI
  builds the image as a separate step.

- **The container runs `tsx`, not a `tsc` bundle.** The whole monorepo resolves `@atp/*` to
  `src/index.ts` through the `exports` field (ADR-003 / CLAUDE.md), so there is no build step
  anywhere; introducing one for the image would mean rewiring every package's exports. A
  welcome consequence: the **deferred "migrations dir must be copied on `tsc` build" item is
  closed by construction** — `packages/store/src/db/migrations/*.sql` is simply present.

- **Verified against real services, not mocks.** dynamodb-local + MinIO were added to
  `docker-compose.dev.yml` and to CI; the suites gate on `ATP_TEST_DYNAMO_ENDPOINT` /
  `ATP_TEST_S3_ENDPOINT` and skip when unset, exactly like the pg-gated suites. The image was
  built and all three modes exercised: `server` (healthz/readyz answered, `docker stop` returned
  in 0.2s with exit 0 — i.e. SIGTERM reached the handler rather than timing out into SIGKILL),
  `worker` (started, claimed, stopped cleanly — note this exercised an *idle* worker; the
  in-flight-run drain is unbounded by design, see the review notes), `migrate` (applied
  `0000_init.sql` to a fresh database and was a no-op on the second run); `ps` inside the
  container confirms `tini` is PID 1.

- **Testing posture — genuinely verified this session.** Full suite with Postgres + dynamodb-local
  + MinIO up: **516 passed | 0 skipped** after the review fixes (P10 left it at 451;
  the pre-review figure was 503). Offline it is 516 minus the gated suites. New tests: `dynamo-tasks` (9), `dynamo-idempotency` (3, incl. a real concurrent
  conditional-put race), `s3-artifacts` (2, the presign one **fetches the URL over plain HTTP**
  with no credentials), `select` (3), `db/url` (5), `dynamo-lifecycle` (2 — the async surface
  end-to-end on DynamoDB task state with the Postgres queue, reading the raw Dynamo item to
  prove it is not quietly still using the `tasks` table), `exporters` (3), `run-task` (2),
  `run-task-submit` (3), `async-lifecycle` (+2: TTL sweep, one-shot worker),

- **Parked items closed this session** (all four, plus the optional escape hatch):
  - **`deleteExpired` TTL sweep** — `sweepExpiredTasks(ctx)` in the worker loop every 5 min.
  - **OTLP exporter wiring** — `resolveExporters(config)`; `OTEL_EXPORTER=otlp` + endpoint,
    fails fast if the endpoint is missing (exporting into the void reads as "healthy").
  - **Cross-process trace propagation** — the W3C `traceparent` rides in `jobs.spec`
    (`RunSpec.trace`) and `withSpan` accepts an explicit `parent`, so agent→server→worker→SUT
    is one trace. Regression test asserts the run span's traceId **and** parent span id.
  - **Migrations dir on build** — closed by construction (see above).
  - **`S3ArtifactStore`** — landed with presigned URLs.

- **New/notable behaviour worth knowing.**
  - `MODE=migrate` is a new role. Migrations do **not** run at service boot on purpose:
    concurrent DDL across a rolling deploy's tasks is how a deploy wedges.
  - `DATABASE_SECRET` (the RDS JSON) is an accepted alternative to `DATABASE_URL` (which wins
    when both are set). Every interpolated field is percent-encoded — credentials *and*
    `dbname` — and a host carrying URL-structural characters is rejected outright, so no field
    can silently re-point the connection.
  - `run_suite` / `run_selection` gained an optional `isolated` input (additive, per §8.6).
  - `startWorker` gained `maxRuns` (the one-shot mode an `ecs:RunTask` task runs in) and the
    handle now exposes `done`.

- **Review (P11 — 2026-07-25): completeness + simplicity (2 subagents + 3 of their children,
  code-review skills).** The first-pass implementation shipped **four Blockers**, all found by
  review and all fixed with regression tests:
  - **Blocker — the `RunTask` escape hatch was entirely non-functional.** `run-task.ts` set
    `WORKER_ONCE`/`ATP_RUN_ID` on the launched task and **nothing read them**: `main-worker.ts`
    called `startWorker(ctx)` with no options, so `maxRuns` was always `undefined`. A launched
    task would loop forever claiming arbitrary jobs — unregistered with the worker service, so
    the autoscaler never scaled it in — exactly what `run-task.ts`'s own comment warned against.
    My test proved the `maxRuns` *mechanism* by calling the seam directly, which is precisely
    how the missing wiring went unnoticed. **Fixed:** `workerOptionsFromConfig(config)` (new,
    directly tested), `claim(db, workerId, {runId})` for a **targeted** claim so the task runs
    the run it was launched for, `idleTimeoutMs` so it exits instead of idling if the pool won
    the race, and a `worker.done` self-exit in `main-worker.ts`.
  - **Blocker — the ALB had no TLS listener.** Synth produced HTTP:80 only, while `deploy.md`
    told operators to `curl https://…` and P10's OAuth bearer tokens would have crossed the
    network in cleartext. **Fixed:** optional `certificateArn` → HTTPS listener + `:80`→`:443`
    redirect, with a test asserting the redirect action.
  - **Blocker — a CloudWatch dimension-key mismatch silently disabled two alarms.**
    `runs_total` is published dimensioned by `status` (`telemetry.ts`) but `PassRateLow` and
    `WorkerErrors` queried `state`. CloudWatch matches dimensions as an exact set, so those
    alarms would have sat in `INSUFFICIENT_DATA` forever — a monitoring gap that reads as
    health. **Fixed** and pinned from *both* sides: `RUN_STATE_ATTRIBUTE` (app) and
    `RUN_STATE_DIMENSION` (infra), each with a test asserting the literal.
  - **Blocker — the image was unwritable for its own default artifact path.** `COPY` ran as
    root, `USER node` came after, and `ARTIFACT_STORE=local` writes to `/app/.atp/artifacts`;
    `touch` there returned `Permission denied`. ECS was unaffected (it sets `s3`), but any
    bare-docker/compose/k8s deployment fails on first run. **Fixed** with `--chown=node:node`
    plus a pre-created owned dir; verified by rebuilding and touching the path as `node`.
  - **Major — the DynamoDB `submitRun` had a worse crash window than I documented.** A crash
    between the idempotency claim and the task create left the key pointing at a run with no
    task; every later resubmission then returned a **fabricated** `state: "working"` while
    `get_run` on that same id threw "no run" — contradictory answers for a run that would never
    execute and never fail. **Fixed:** the claim is now *adopted* when no task exists (create +
    enqueue proceed under the same run id), so the strand self-heals and idempotency still
    holds. Regression test included.
  - **Major — only the credentials were percent-encoded in `resolveDatabaseUrl`**, not `dbname`
    or `host`, though the same mechanism applies: `dbname: "atp#staging"` silently connects to
    `atp`, and an `@` in the host re-points the connection at whatever follows. **Fixed** —
    dbname encoded, structurally-unsafe host rejected, both tested.
  - **Major — the image `HEALTHCHECK` was MODE-blind**, marking healthy workers `unhealthy`.
    **Fixed** (probe only in server mode); verified `health=healthy` for a worker container.
  - **Major (documented, not fixed) — metrics never reach CloudWatch by default.** The app
    exports OTLP only and **this repo's CDK provisions no collector**, so `queue_depth`
    never arrives and the worker's step-scaling silently never fires. Documented prominently in
    `deploy.md` and parked; provisioning an ADOT sidecar is real work I deliberately did not
    fold into this pass.
  - **Major (documented) — the worker's SIGTERM drain is unbounded**: it stops claiming new
    work and waits for the current run, never aborting the in-flight request. `stopTimeout`
    must exceed the longest expected run. Now stated in `deploy.md`.
  - Minors fixed: the `update(runId, {})` empty-patch divergence between backends (Postgres
    bumped `updatedAt`, DynamoDB didn't — the store-selection contract forbids that), an
    `iam:PassedToService` condition on `PassRole`, `ecs:RunTask` granted on the task-definition
    *family* rather than a pinned revision (a pinned one breaks the next deploy), `.once` signal
    handlers, endpoint config fields validated as URLs, and the task store no longer constructed
    when no database is configured.
  - Test-quality audit found no false claims in this file, but two real coverage gaps, both now
    closed: `deleteExpired`'s **pagination** loop (the old test seeded 3 items, so the second
    `Scan` page never ran — a configurable `scanPageSize` now forces it) and the Dynamo
    enqueue-failure compensation path (now exercised by closing the pool for real; the logic
    turned out to be correct, it was simply untested).
  - Simplicity review: applied the dead `ArtifactStoreSelection.close()` removal (nothing ever
    called it) and the shared `resolveExpiry`. It argued **against** merging the mirrored
    Dynamo/Postgres task-store test suites — they gate on different env vars so either runs
    offline, and a union skip condition would be more complex than the duplication — and found
    the CDK stacks, `buildUpdate`, and `EcsLike` right-sized. Agreed on all three.
  - Gate after fixes: **516 passed | 0 skipped** with all services up; typecheck / lint /
    compile / synth / `docker build` green.

- **Deferred / not done (parked in `docs/deferred.md`):** a real `tsc`/bundle build for the
  image if start-up cost ever matters; `S3ArtifactStore` has no lifecycle/multipart handling for
  very large traces; the `Data` stack provisions DynamoDB tables even in `postgres` mode (cheap
  on-demand, but noise); no smoke-test-after-deploy step in the runbook; and the pre-existing
  P3/P8/P10 items that P11 did not touch.
