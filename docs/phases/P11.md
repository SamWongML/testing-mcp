**Handoff notes (P11 — 2026-07-25):**

- **Shape.** P11 is the deployment layer. Two new adapters behind the P6 seams
  (`DynamoTaskStore` → `TaskStateStore`, `S3ArtifactStore` → `ArtifactStore`), one selection
  module that makes the backing a config choice, a CDK app, and one container image that runs
  three roles. No representation change; the engine stays pure (no AWS import anywhere under
  `packages/engine`). New deps: `@aws-sdk/{client-dynamodb,lib-dynamodb,client-s3,s3-request-presigner}`
  on `@atp/store`, `@aws-sdk/client-ecs` + the two OTLP exporters on `@atp/mcp-server`,
  `aws-cdk-lib`/`constructs`/`aws-cdk` on the new `infra` workspace package.

- **Everything stays off by default.** `TASK_STORE=postgres` and `ARTIFACT_STORE=local` are the
  defaults, so dev/test/CI run exactly as they did in P10. `RUN_TASK_ENABLED`, `AUTH_ENABLED`,
  and `OTEL_ENABLED` likewise default off.

- **Files.**
  - `packages/store/src/aws/` — `attributes.ts` (the §16.2 item shape; `state`/`error`/`ttl` are
    DynamoDB **reserved words**, so every expression aliases its names), `client.ts`,
    `dynamo-tasks.ts`, `dynamo-idempotency.ts`, `s3-artifacts.ts`, `select.ts`, `test-aws.ts`
    (exported as `@atp/store/testing`).
  - `packages/store/src/db/url.ts` — `resolveDatabaseUrl`: prefers `DATABASE_URL`, else derives
    one from the RDS-managed Secrets Manager JSON.
  - `packages/mcp-server/src/` — `exporters.ts` (console↔OTLP selection), `run-task.ts` (the
    §11.3 mode-2 launcher), `main-migrate.ts` (`MODE=migrate`), plus `taskStoreFor` in
    `tasks.ts` and trace propagation in `telemetry.ts`.
  - `infra/` — `bin/app.ts`, `src/{network,data,ecs,observability}-stack.ts`, `src/metrics.ts`,
    `cdk.json`. `Dockerfile` + `docker-entrypoint.sh` at the repo root.

- **`DynamoTaskStore` design notes.** Writes go through `UpdateItem`, not `PutItem`, even for
  the full-replace `put` — that is what lets `created_at` survive a replace via
  `if_not_exists` (SEP-1686 `Task.createdAt` must be *first* creation, which the Postgres store
  gets free from an insert-only column default). `create()` is a conditional `PutItem`
  (`attribute_not_exists`), the direct analogue of `ON CONFLICT DO NOTHING`. Reads are
  `ConsistentRead: true`: a stale replica read could resurrect a cancelled run. `deleteExpired`
  is a real scan-and-delete sweep, because native DynamoDB TTL reaps only "within a few days"
  and never at all on dynamodb-local — both run, and deleting an already-deleted key is a no-op.

- **The store-selection seam (exit criterion 3).** `createTaskStoreProvider(config)` returns
  `{ forDb, transactional, idempotency, close }`. `forDb(db)` takes the caller's Db/transaction
  because the Postgres store must **join** the caller's transaction (that is what makes
  create-task + enqueue atomic); DynamoDB ignores it. `submitRun` branches on `transactional`:
  the Postgres path is unchanged, and the DynamoDB path claims an idempotency key first (so the
  run id is minted *independently* of the key — the stage-1 path had to make the key **be** the
  run id), creates the task item, then enqueues, failing the task if the enqueue throws.
  Everything else in the package reads task state through `taskStoreFor(ctx, db)`.

- **Two cross-stack dependency cycles, both real.** (a) `data.database.connections.allowFrom(service)`
  puts an ingress rule referencing an `ecs` construct into the `data` stack, while `ecs` already
  reads `data`'s table ARNs. (b) The pattern-created ALB security group did the same to
  `network`. Both are fixed by having `NetworkStack` own the app **and** ALB security groups and
  constructing the ALB explicitly. Rule of thumb recorded in `.claude/rules/infra.md`: grant
  ingress **downward**, never upward.

- **`cdk synth` is deliberately Docker-free.** The ecs stack references a pushed `imageUri`
  rather than `ContainerImage.fromAsset`, so CI can synth on every PR without a daemon. CI
  builds the image as a separate step.

- **The container runs `tsx`, not a `tsc` bundle.** The whole monorepo resolves `@atp/*` to
  `src/index.ts` through the `exports` field (ADR-003 / CLAUDE.md), so there is no build step
  anywhere; introducing one for the image would mean rewiring every package's exports. A
  welcome consequence: the **deferred "migrations dir must be copied on `tsc` build" item is
  closed by construction** — `packages/store/src/db/migrations/*.sql` is simply present.

- **Verified against real services, not mocks.** dynamodb-local + MinIO were added to
  `docker-compose.dev.yml` and to CI; the suites gate on `ATP_TEST_DYNAMO_ENDPOINT` /
  `ATP_TEST_S3_ENDPOINT` and skip when unset, exactly like the pg-gated suites. The image was
  built and all three modes exercised: `server` (healthz/readyz answered, `docker stop` returned
  in 0.2s with exit 0 — i.e. SIGTERM reached the handler rather than timing out into SIGKILL),
  `worker` (started, claimed, stopped cleanly), `migrate` (applied `0000_init.sql` to a fresh
  database and was a no-op on the second run); `ps` inside the container confirms `tini` is PID 1.

- **Testing posture — genuinely verified this session.** Full suite with Postgres + dynamodb-local
  + MinIO up: **503 passed | 0 skipped** (P10 left it at 451). Offline it is 503 minus the
  gated suites. New tests: `dynamo-tasks` (9), `dynamo-idempotency` (3, incl. a real concurrent
  conditional-put race), `s3-artifacts` (2, the presign one **fetches the URL over plain HTTP**
  with no credentials), `select` (3), `db/url` (5), `dynamo-lifecycle` (2 — the async surface
  end-to-end on DynamoDB task state with the Postgres queue, reading the raw Dynamo item to
  prove it is not quietly still using the `tasks` table), `exporters` (3), `run-task` (2),
  `run-task-submit` (3), `async-lifecycle` (+2: TTL sweep, one-shot worker),
  `observability` (+1: cross-process trace), `infra` (17 template assertions). `pnpm typecheck`,
  `pnpm lint`, `pnpm compile`, `pnpm synth`, and `docker build` all green.

- **Parked items closed this session** (all four, plus the optional escape hatch):
  - **`deleteExpired` TTL sweep** — `sweepExpiredTasks(ctx)` in the worker loop every 5 min.
  - **OTLP exporter wiring** — `resolveExporters(config)`; `OTEL_EXPORTER=otlp` + endpoint,
    fails fast if the endpoint is missing (exporting into the void reads as "healthy").
  - **Cross-process trace propagation** — the W3C `traceparent` rides in `jobs.spec`
    (`RunSpec.trace`) and `withSpan` accepts an explicit `parent`, so agent→server→worker→SUT
    is one trace. Regression test asserts the run span's traceId **and** parent span id.
  - **Migrations dir on build** — closed by construction (see above).
  - **`S3ArtifactStore`** — landed with presigned URLs.

- **New/notable behaviour worth knowing.**
  - `MODE=migrate` is a new role. Migrations do **not** run at service boot on purpose:
    concurrent DDL across a rolling deploy's tasks is how a deploy wedges.
  - `DATABASE_SECRET` (the RDS JSON) is an accepted alternative to `DATABASE_URL`; credentials
    are percent-encoded, so a generated password containing `#` or `/` cannot corrupt the URL.
  - `run_suite` / `run_selection` gained an optional `isolated` input (additive, per §8.6).
  - `startWorker` gained `maxRuns` (the one-shot mode an `ecs:RunTask` task runs in) and the
    handle now exposes `done`.

- **Deferred / not done (parked in `docs/deferred.md`):** a real `tsc`/bundle build for the
  image if start-up cost ever matters; `S3ArtifactStore` has no lifecycle/multipart handling for
  very large traces; the `Data` stack provisions DynamoDB tables even in `postgres` mode (cheap
  on-demand, but noise); no smoke-test-after-deploy step in the runbook; and the pre-existing
  P3/P8/P10 items that P11 did not touch.
