**Handoff notes (P10 — 2026-07-25):**

- **Shape.** P10 is the production-posture layer, additive on P8/P9: an OAuth gate + scope checks
  on the MCP surface, an audit trail on run-invoking calls, and full Pino/OTel observability. No
  engine/schema representation change; the engine **stays pure** — SUT spans come from undici
  auto-instrumentation (diagnostics_channel), not an engine import. New deps on `@atp/mcp-server`:
  `jose`, `pino`, `@opentelemetry/{api,sdk-trace-node,sdk-trace-base,sdk-metrics,resources,
  semantic-conventions,instrumentation,instrumentation-undici}`. No new store deps.

- **Everything is gated off by default** (`AUTH_ENABLED`/`OTEL_ENABLED` default `false` via
  `z.stringbool()`), so the whole prior surface runs unchanged in dev/test. `ctx.authn`/
  `ctx.logger`/`ctx.telemetry` are optional context fields; when absent the handlers no-op the
  guard/audit/span paths. This is the "internal-deployment simplification" escape hatch (ADR-007).

- **Files (all `packages/mcp-server/src/` unless noted):**
  - `auth.ts` — the pure core: `parseBearerToken`, `SCOPES` (`test:read`/`test:run`),
    `assertScope`/`ScopeError`, `protectedResourceMetadata` (RFC 9728) + `wwwAuthenticate`,
    `createAuthenticator` (jose `jwtVerify` enforcing signature/issuer/**audience = RFC 8707
    resource**/expiry → SDK `AuthInfo`). Side-effect free (remote JWKS is lazy).
  - `guard.ts` — handler-side `guardScope(ctx, extra, scope)` (no-op off-auth), `principalOf`,
    `auditRun(ctx, extra, {action, entryId, params})` (no-op without a db). `extra.authInfo` is
    the SDK-validated token the transport threads in.
  - `logging.ts` — `createLogger` (Pino JSON, `REDACT_PATHS` scrubbing auth headers/tokens/
    `secrets` top-level + one-level-nested, `[REDACTED]` censor). Correlation ids attach via
    `logger.child({runId,taskId,traceId,nodeId})`.
  - `telemetry.ts` — `initTelemetry` (NodeTracerProvider + MeterProvider, injectable exporters:
    console by default, in-memory in tests; registers undici auto-instrumentation), `withSpan`
    (active-span wrapper: nests children, records exception+ERROR on throw, always ends),
    `RunMetrics` (`runs_total`/`run_duration_ms`/`assertion_failures_total{test}`/`queue_depth`
    sync gauge).
  - `context.ts` — `ServerContext` gained `authn?: AuthContext` / `logger?` / `telemetry?`.
  - `http.ts` — when `ctx.authn`: serves `/.well-known/oauth-protected-resource`, requires a
    valid bearer on `/mcp` (else `401` + `WWW-Authenticate: Bearer resource_metadata="…"`), and
    passes the validated `authInfo` into `transport.handleRequest(req, {authInfo})`. When
    `ctx.telemetry`: wraps each `/mcp` request in an `mcp …` span.
  - `bootstrap.ts` — `buildAuthContext(config)` (lazy authenticator from `AUTH_ISSUER`/
    `AUTH_RESOURCE`/`AUTH_JWKS_URI`; throws if enabled-but-unconfigured), wired into
    `buildContext`. `main.ts`/`main-worker.ts` build the logger + (optional) telemetry and inject
    them (never `buildContext`, which stays offline/side-effect-free).
  - `worker.ts` — a run span (`run <entryId>`, `atp.run_id`/`atp.entry_id` attrs) wraps
    `executeEntry` so the engine's undici SUT calls nest under it; a `child({runId,taskId})`
    logger logs claim/node/terminal; `recordRunMetrics` bumps run + assertion-failure metrics;
    `claimAndRun` samples `queue_depth` each poll.
  - Scope gating added to every tool/resource handler: **READ** on `list_tests`/`describe_test`/
    `get_report`/`list_runs`/`get_run`/`get_run_result`/resources; **RUN** (+`auditRun`) on
    `run_test`/`run_suite`(createTask)/`run_selection`/`cancel_run`.
  - Store: `audit.ts` (`recordAudit`/`listAudit` over the existing `audit_log` table) and
    `queueDepth(db)` in `queue.ts` (ready-to-claim jobs — the autoscaling signal).

- **SDK integration facts (verified against installed 1.29.0 `.d.ts`, not memory).**
  `WebStandardStreamableHTTPServerTransport.handleRequest(req, {authInfo})` accepts a
  pre-validated `AuthInfo`; it surfaces on every handler's `extra.authInfo` (both
  `ToolCallback` and the task handlers' `CreateTaskRequestHandlerExtra`). So we do our own
  Hono-side jose verification (the SDK's `bearerAuth` middleware is Express-only) and thread the
  result through — no SDK auth router needed.

- **Testing posture — genuinely verified against live Postgres this session** (Docker was up on
  `:5432` with `atp/atp`). `pnpm test` with `ATP_TEST_DATABASE_URL` set: **438 passed | 0
  skipped**; offline: **395 passed | 43 pg-gated skips**. New tests: `auth.test.ts` (13 — bearer
  parse, scope, RFC 9728 metadata, jose verify incl. wrong-key/wrong-audience/wrong-issuer/
  expired), `auth-http.test.ts` (6 — real Streamable-HTTP round-trip: metadata endpoint, 401
  unauth, 401 expired, read-token→`list_tests`, read-only→`run_test` **denied** naming
  `test:run`, run-token→`run_test` **passed**), `logging.test.ts` (4), `telemetry.test.ts` (3 —
  span nesting MCP→run→SUT, exception recording, run+queue metrics), `observability.test.ts` (2,
  pg-gated — a full async run emits a run span with **nested undici SUT spans in one trace** +
  runId-correlated logs + `runs_total`/`queue_depth`/`run_duration_ms`; and a `run_test` writes
  an audit row), `bootstrap.test.ts` (+4 `buildAuthContext`), `store/audit.test.ts` (3),
  `queue.test.ts` (+1 `queueDepth`). All three exit criteria demonstrated: unscoped calls
  rejected + scoped succeed; a full async run emits correlated logs/spans/metrics via in-memory
  (console-equivalent) exporters; prior tests green with auth off by default.

- **Deferred / not done (parked in `docs/deferred.md`):**
  - **Cross-process trace propagation** — the worker's run span starts a *new* trace, not linked
    to the server's `mcp` request span (they are different processes; the enqueue→claim hop
    doesn't carry W3C `traceparent`). Full agent→server→worker→SUT correlation needs the
    trace context serialized into `jobs.spec`. P11 hardening.
  - **OTLP exporter wiring** — `initTelemetry` defaults to console/in-memory; the OTLP→X-Ray/
    CloudWatch exporter selection lands with the P11 CDK/observability stack.
  - The P8 `deleteExpired` TTL sweep is still unwired (a periodic sweep in the worker loop) —
    operational GC, P11.

- **Exact next step (P11): AWS infra + DynamoDB.** Dockerfile (`MODE=server|worker`, tini,
  graceful shutdown), CDK stacks (network/data/ecs/observability), `DynamoTaskStore` implementing
  the P6 `TaskStateStore` seam + idempotency table, store selection by config, `cdk synth` in CI,
  `docs/deploy.md`. Read plan §P11 + research §17 (all), §16.2, §18, §11.3, ADR-004/005/008. The
  P10 `queue_depth` metric is the worker-autoscaling signal the `ecs` stack scales on; the OTLP
  exporter + cross-process trace propagation noted above belong here.
